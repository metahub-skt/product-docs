# MetaHub 0.5.8 (2026-10-22)

Release Note

## What's New

MetaHub 0.5.8 은 **관리 콘솔의 사용성을 크게 개선하고 Polaris 운영 설정을 chart values 로 받을 수 있게 한** 릴리즈입니다. 0.5.7 과 0.5.8 의 변경을 함께 담았습니다. 관리 콘솔(Polaris Console)은 카탈로그·테이블 목록을 페이지 단위로 탐색하고, 카탈로그·네임스페이스·테이블·principal 을 한 곳에서 검색할 수 있게 되었습니다. 접근 제어 화면도 실수로 관리 계정을 지우거나 역할이 남는 일이 없도록 보완되었습니다.

함께 Polaris 의 graceful shutdown, 오토스케일 속도, LoadBalancer 설정처럼 그동안 환경마다 chart 밖에서 손으로 맞추던 운영 설정을 values 로 지정할 수 있게 되었습니다. 새 설정은 모두 기본 꺼짐이라 기존 환경의 동작은 바뀌지 않습니다.

## Breaking Changes

- 이번 릴리즈에 breaking change 없음 (0.5.6 → 0.5.8 기준). values 인터페이스와 기본값은 변경되지 않았으며, 새 설정은 모두 기본 꺼짐입니다. 다만 관리 콘솔 개선은 콘솔 이미지 태그를 함께 올려야 반영됩니다(Upgrade Notes 참조).

## Features

- **관리 콘솔에서 카탈로그·테이블 목록을 페이지 단위로 탐색**  
  Catalog Explorer 와 각 목록 화면이 페이지 단위로 나뉘어 항목이 많은 카탈로그도 빠르게 열립니다. Polaris 가 페이징을 지원하면 서버에서, 지원하지 않으면 화면에서 나눕니다. 페이지 크기는 화면마다 따로 기억합니다.  
  *구현: 관리 콘솔 1.6.0 의 서버 페이징 + 클라이언트 폴백.*
- **관리 콘솔 전역 검색**  
  카탈로그·네임스페이스·테이블·principal 을 하나의 검색창에서 찾고 바로 이동할 수 있습니다. 키보드 단축키로 여는 명령 팔레트도 제공합니다.  
  *구현: 관리 콘솔 1.6.0 GlobalSearch · Command Palette.*
- **브라우저에서 난 관리 콘솔 오류를 서버 로그로 수집**  
  사용자 브라우저에서 발생한 콘솔 오류를 서버 로그에 JSON 한 줄로 남겨, 사용자 화면을 보지 않고도 문제를 추적할 수 있습니다. 클라이언트당 초당 5건으로 제한되어 로그 폭주를 막습니다. 기본값은 꺼짐입니다.  
  *구현: `polaris-console.env.remoteLoggingEnabled` → `POST /client-logs`, nginx stdout. 제한 초과 시 429.*
- **Polaris 종료 시 처리 중인 요청을 마치고 내려가도록 설정 가능**  
  롤링 업데이트나 축소로 Polaris 파드가 내려갈 때, 새 요청을 받지 않은 상태로 진행 중인 요청을 끝낸 뒤 종료하도록 대기 시간을 지정할 수 있습니다. 값의 조합이 잘못되어 이 기능이 조용히 꺼지는 경우는 설치 단계에서 오류로 알려 줍니다. 기본값은 꺼짐입니다.  
  *구현: `polaris.gracefulShutdown.{enabled,delaySeconds,timeoutSeconds,terminationGracePeriodSeconds}` → `QUARKUS_SHUTDOWN_DELAY/TIMEOUT` + pod `terminationGracePeriodSeconds`.*
- **Polaris 오토스케일 확장·축소 속도 지정**  
  부하가 늘 때 즉시 늘리고 줄어들 때는 천천히 줄이는 식으로 Polaris 의 오토스케일 동작을 환경에 맞게 정할 수 있습니다. Catalog Gateway 와 같은 형식입니다.  
  *구현: `polaris.autoscaling.behavior`.*
- **Polaris Service 에 라벨 지정과 LoadBalancer nodePort 할당 억제**  
  LoadBalancer IP 를 라벨로 고르는 네트워크 환경에서 Polaris Service 에 필요한 라벨을 붙이고, 쓰지 않는 nodePort 가 할당되지 않게 할 수 있습니다.  
  *구현: `polaris.service.labels`, `polaris.service.loadBalancer.allocateNodePorts`(Service 타입이 LoadBalancer 일 때만 적용).*
- **Hive 메타스토어 연동에 Polaris 와 다른 S3 자격증명 사용**  
  Hive 메타스토어 쪽 오브젝트 스토리지 계정이 Polaris 와 다른 환경에서도 연동 전용 자격증명을 지정해 쓸 수 있습니다. 기존 Secret 경로는 그대로 동작합니다.  
  *구현: `polaris.hiveFederation.s3.credentials.{accessKeyId,secretAccessKey}` → core-site.xml `fs.s3a.access.key/secret.key`.*
- **사설 이미지 레지스트리 접속 Secret 을 chart 가 생성**  
  사설 레지스트리에서 Polaris 이미지를 받는 환경에서 접속 Secret 을 미리 만들지 않고 chart values 로 생성할 수 있습니다.  
  *구현: `polaris.private.registry.{createSecret,secret}` → `kubernetes.io/dockerconfigjson` Secret.*

## Improvements

- **관리 콘솔 접근 제어 화면 보완**  
  principal 을 만들면 자격증명을 바로 확인하는 창이 뜹니다. principal 을 지우면 연결된 역할도 함께 회수되고, 최초 관리 계정(root principal)은 화면에서 수정·삭제할 수 없습니다. 권한 조회를 병렬로 처리해 화면이 더 빨리 열립니다.  
  *구현: 관리 콘솔 1.6.0 Access Control.*
- **관리 콘솔 화면 안정성·사용성 개선**  
  로딩 중 화면 골격과 빈 목록 안내가 표시되고, 사이드바 폭과 접힘 상태가 유지됩니다. 브라우저 저장소 접근이 막힌 사설 모드나 기업용 브라우저에서도 콘솔이 열립니다.  
  *구현: 관리 콘솔 1.6.0 Skeleton · EmptyState · `useSidebarState` · sessionStorage 접근 보호.*
- **Polaris 메트릭 수집 설정 오류 방지**  
  메트릭이 꺼진 상태에서 수집 대상(ServiceMonitor)만 만들어져 수집이 계속 실패하던 구성을 막았습니다. 메트릭과 수집 대상을 둘 다 켰을 때만 수집 대상을 만들고, 수집 주기를 비워 두면 30초를 씁니다.  
  *구현: `polaris.metrics.enabled` 와 `polaris.serviceMonitor.enabled` 가 모두 true 일 때만 ServiceMonitor 생성 — 조치 신호: Upgrade Notes 참조.*

## Fixes

- **관리 콘솔에서 속성 수정이 400/409 로 실패하던 문제 해결**  
  카탈로그·네임스페이스 속성 수정이 오류로 실패하던 문제와, 인증·화면 이동 중 일부 화면이 비정상 표시되던 문제를 수정했습니다.  
  *구현: 관리 콘솔 1.6.0.*
- **역할 멤버 목록에 실제로 할당되지 않은 사용자가 보이던 문제 해결**  
  역할 생성·멤버 추가 시 Polaris 에 계정이 없어 할당에 실패한 사용자도 멤버로 표시되었습니다. 이제 할당에 성공한 사용자만 멤버로 기록됩니다.  
  *구현: Catalog Gateway 역할 멤버 저장 로직.*
- **권한 수동 동기화와 역할 변경 직후 이전 권한이 반영되던 문제 해결**  
  권한 데이터 수동 동기화를 요청해도 이전 상태가 그대로 전달되거나, 역할에 멤버·리소스를 추가한 직후 권한 확인에 반영되지 않는 경우가 있었습니다. 이제 수동 동기화는 항상 최신 상태로 다시 만들고, 역할 변경 요청은 반영이 끝난 뒤 응답합니다.  
  *구현: Catalog Gateway `POST /v1/opal/sync` 의 스냅샷 재생성, 역할 멤버·리소스 추가 시 반영 대기.*

## Known Issues

- **테이블 수가 많은 환경에서 전체 테이블 목록 조회 시 Catalog Gateway 메모리 한도 초과 가능**  
  전체 테이블 목록 API(`/v1/catalogs/all_tables`)는 결과 상한 없이 모두 모아 응답하며, 검색어가 카탈로그 이름에도 부분 일치합니다. 짧은 검색어로 10만 건 이상이 걸리면 요청 하나가 약 0.6~0.95 GB 의 메모리를 쓰고, 상용급 Kubernetes 환경의 1,000 동시 사용자 부하테스트(2026-10-16)에서 Gateway Pod 2개가 메모리 한도(8Gi)를 넘어 재시작했습니다. 환경 values 의 bulkhead 에 이 경로 전용 그룹(동시 1건)을 두고, 전체 테이블 수와 worker 수에 맞춰 메모리 한도를 정하면 회피할 수 있습니다. 결과 상한과 메모리 절감은 후속 릴리즈에서 다룹니다.
- **큰 카탈로그의 전체 목록 조회가 몰리면 작은 카탈로그의 같은 조회 일부가 503 으로 거절됨**  
  위 bulkhead 그룹은 경로 단위라, 응답에 수 초가 걸리는 큰 카탈로그 조회가 슬롯을 점유하면 같은 경로의 작은 조회가 대기 후 거절됩니다(부하테스트에서 1.5~3.9%). 다른 API 는 영향을 받지 않습니다. 수정은 보류 상태입니다.
- **역할(role) 등록 요청의 응답 지연 원인 미확정**  
  역할 수천 건 규모의 환경에서 역할 등록 1건에 약 14초가 걸리고 관리 목록 조회가 간헐적으로 500 을 냅니다(2026-10-16 측정). 권한 평가와 MCP 범위 적용 등 읽기 경로에는 영향이 없습니다. 원인 분리는 진행 중입니다.
- **기존 UI 수집 소스에 구체 CLI 버전이 지정되어 있으면 수집 실행 불가**  
  DataHub v1.7 계열에서 수집 소스의 `config.version` 이 `1.6.0` 처럼 구체 버전이면 executor 가 패키지 다운로드 단계에서 실패합니다. 값을 `native` 로 바꾸면 회피할 수 있습니다.
- **시맨틱(벡터) 검색은 켠 상태 미검증**  
  0.5.1 에서 추가된 on/off 설정은 꺼진 상태로만 검증되었습니다.
- **kafka-setup 이미지 버전 지정 불가**  
  upstream DataHub chart 가 kafka-setup 이미지를 앱 버전과 별도로 고정(`v1.2.0.1`)하므로 버전을 바꿀 수 없습니다. upstream 의 의도된 값이며 결함이 아닙니다.
- **메타데이터 서비스 인증 기본 비활성, SSO/OIDC 미연계**  
  `metadata_service_authentication.enabled` 기본값은 `false` 이고 Frontend 는 로컬 계정으로 동작합니다. 상용 전환 시 결정이 필요한 항목으로 추적합니다.
- **데이터베이스·정책 서버 접속 정보가 values 에 평문으로 저장됨**  
  PostgreSQL, Polaris 최초 관리 계정, OPAL 브로드캐스트 접속 정보가 values 평문입니다. 이번 릴리즈의 Hive 메타스토어 연동 전용 S3 자격증명과 사설 레지스트리 Secret 설정도 values 에 평문으로 들어갑니다. Secret 또는 외부 비밀 저장소로 분리하는 작업을 추적합니다.

## Deprecations

- **MCP sse 인스턴스(`datahub-mcp`) — 0.6 릴리즈에서 제거 예정 (2026-11 계획)**  
  MCP 클라이언트가 Gateway 경유 http 인스턴스(`datahub-mcp-http`, `/mcp` + JWT)로 전환되면 공유 토큰 기반 sse 인스턴스와 `/sse` 전제를 제거합니다. 그 릴리즈가 breaking change 가 되며, 해당 Release Note 에서 다시 공지합니다. 제거 전에 `/sse` 를 쓰는 클라이언트를 먼저 옮기십시오.

## Upgrade Notes

**0.5.6 → 0.5.8**

- DataHub 와 Polaris 앱 버전 변경이 없습니다(DataHub v1.7.0.1, Polaris 1.6.0 유지). 스키마 변경과 초기화 Job 재실행이 필요하지 않습니다.
- 환경의 chart 버전 pin 을 0.5.8 로 올리십시오. 업그레이드 시 Polaris 와 관리 콘솔이 한 번씩 롤링 재시작합니다.
- **관리 콘솔 개선을 쓰려면 `polaris-console.image.tag` 를 1.6.0 이후 빌드 태그로 함께 올리십시오.** chart 만 올리면 콘솔은 이전 화면 그대로입니다.
- `polaris.serviceMonitor.enabled: true` 로 두고 `polaris.metrics.enabled` 를 켜지 않은 환경은 업그레이드 후 Polaris ServiceMonitor 가 사라집니다. 메트릭을 수집하려면 `polaris.metrics.enabled: true` 를 함께 지정하십시오.
- **graceful shutdown 을 켜는 경우** `polaris.livenessProbe.terminationGracePeriodSeconds`(기본 30)를 `polaris.gracefulShutdown.terminationGracePeriodSeconds`(기본 60) 이상으로 함께 올리십시오. 낮으면 chart 렌더가 오류로 멈춥니다. 켜면 파드 종료가 delay + timeout(기본 40초)만큼 길어집니다.
- **Hive 메타스토어 연동 전용 S3 자격증명**은 ConfigMap 에 평문으로 렌더됩니다. 같은 키를 Secret 경로(`polaris.hiveFederation.s3.secret.name`)로 줄 수 있으면 그쪽을 쓰십시오.
- **사설 레지스트리 Secret 생성**은 values 에 레지스트리 비밀번호를 넣어야 합니다. 클러스터에 미리 만든 Secret 을 `imagePullSecrets` 로 지정할 수 있으면 그쪽을 쓰십시오.
- **브라우저 오류 수집을 켜는 경우** `polaris-console.env.remoteLoggingEnabled: "true"` 로 지정하십시오. 사용자 수에 비례해 콘솔 로그가 늘어나므로 로그 수집기 용량을 먼저 확인하십시오. 이미지 재빌드는 필요 없습니다.

**이전 버전(0.4.x)에서 올리는 경우**

- 0.5.0 에서 DataHub 가 v1.6.0 에서 v1.7.0.1 로 바뀌었습니다. 같은 values 로도 결과가 달라지므로 **chart 버전과 values 를 함께** 올리십시오. 업그레이드 시 system-update(무중단 업그레이드 18단계)가 실행됩니다.
- DataHub v1.7 은 `DATAHUB_SYSTEM_CLIENT_ID` 와 `DATAHUB_SYSTEM_CLIENT_SECRET` 환경 변수가 없으면 GMS 와 system-update 가 시작하지 못합니다. 메타데이터 서비스 인증이 꺼진 상태에서는 chart 가 이 값을 렌더하지 않으므로 각 컴포넌트의 `extraEnvs` 로 넣으십시오. 환경 values 가 같은 컴포넌트의 `extraEnvs` 를 정의하면 그 목록에도 두 항목을 추가하십시오.
- 기존 UI 수집 소스의 `config.version` 을 `native` 로 바꾸십시오(Known Issues 참조).
- 0.5.1~0.5.6 에서 추가된 설정(`semantic_search`, `datahub-mcp-http`, `mcpScope`, `opa.internalRoledataWithDatahub`, `polaris.dbInit`)은 모두 기본 꺼짐이라 버전만 올리면 동작이 바뀌지 않습니다.
