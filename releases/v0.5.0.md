# MetaHub 0.5.0 (2026-10-07)

Release Note

## What's New

MetaHub 0.5.0 은 **메타데이터 플랫폼 코어를 DataHub v1.6.0 에서 v1.7.0.1 로 올린** 릴리즈입니다. v1.6.0 에서는 역할(role) 수가 늘수록 UI 응답과 수집 작업이 함께 느려졌는데, 권한 평가 과정에서 역할 기반 정책마다 역할을 다시 해석하던 결함이 원인이었고 upstream v1.7.0 에서 수정되었습니다. 상용급 Kubernetes 환경의 전후 비교에서 GMS 요청당 CPU 시간이 2.4 초에서 22 ms 로 줄었고, 역할을 3,000 개 추가한 조건에서 사용자 조회 응답이 201~285 ms 에서 52~65 ms 로 돌아왔습니다(부하테스트 검증, 2026-10-07·2026-10-12).

업그레이드와 함께 UI 수집이 외부 패키지 저장소 없이 실행되도록 기본 방식을 바꾸었고, MCP 서버는 upstream 공식 이미지로 교체되었습니다. 이 릴리즈는 minor 버전이 올라간 릴리즈로, 같은 values 로 배포해도 결과가 달라지는 변경을 포함합니다(업그레이드 시 조치 필요 — Breaking Changes 참조).

## Breaking Changes

- **chart 버전과 values 를 함께 올리기 필요**  
  values 키가 삭제되지는 않았지만, DataHub 버전과 upstream chart 1.1.x 의 기본값(무중단 업그레이드 경로, 시크릿 복호화 가드 ENFORCE, UI 다국어)이 바뀌어 같은 values 로 배포해도 결과가 달라집니다. chart 버전을 고정(pin)하는 환경은 values 만 올리면 GMS 가 v1.7 로 바뀌지 않으므로, chart 버전 pin 과 values 를 같은 변경으로 올리십시오.
- **`extraEnvs` 를 정의한 환경은 시스템 클라이언트 환경 변수 2개 추가 필요**  
  DataHub v1.7 은 `DATAHUB_SYSTEM_CLIENT_ID` 와 `DATAHUB_SYSTEM_CLIENT_SECRET` 이 없으면 GMS·초기화 Job 등이 시작하지 못합니다. chart 가 6개 컴포넌트의 `extraEnvs` 에 두 항목을 기본으로 넣지만, `extraEnvs` 는 목록이라 환경 values 가 어떤 컴포넌트의 `extraEnvs` 를 정의하면 그 목록으로 통째로 바뀝니다. 해당 컴포넌트의 환경 values 목록에 두 항목(값은 chart 가 생성하는 `datahub-auth-secrets` 참조)을 추가하십시오. 빠진 컴포넌트만 시작에 실패합니다.
- **기존 UI 수집 소스의 CLI 버전을 `native` 로 변경 필요**  
  구체 버전이 지정된 수집 소스는 실행에 실패하므로(Known Issues 참조) 업그레이드 뒤 각 소스의 `config.version` 을 `native` 로 바꾸십시오.
- **브라우저·사용자 토큰으로 저장된 시크릿 값 조회 불가**  
  시크릿 복호화 가드가 ENFORCE 로 켜져 브라우저 세션과 개인 액세스 토큰(PAT)으로는 시크릿 값을 읽을 수 없습니다. 수집 실행기 등 시스템 클라이언트는 영향이 없습니다. 사용자 토큰으로 시크릿 값을 읽는 자동화가 있다면 시스템 클라이언트로 옮기십시오.

그 외 breaking change 는 없습니다 (0.4.21 → 0.5.0 기준).

## Features

- **MCP 서버 전송 방식 선택 지원 (sse 또는 http)**  
  AI 도구 연동용 MCP 서버를 기존 sse 방식 그대로 쓰거나, 요청마다 사용자 토큰을 전달하는 http 방식(`/mcp`)으로 띄울 수 있습니다. 기본값은 sse 라 기존 `/sse` 클라이언트는 변경 없이 그대로 동작합니다.  
  *구현: datahub-mcp subchart 0.1.3 의 `transport: sse|http`, 이미지는 upstream 공식 `acryldata/mcp-server-datahub:v0.7.1`(자체 빌드 이미지 v0.4.0 은 더 이상 쓰지 않습니다). 두 방식 공통으로 `GET /health` 프로브를 씁니다.*

## Improvements

- **메타데이터 플랫폼 코어 DataHub v1.7.0.1 로 업그레이드**  
  GMS·Frontend·이벤트 컨슈머·초기화 Job·수집 실행기가 모두 v1.7.0.1 로 올라갑니다. 역할 수에 비례하던 지연이 사라지고(What's New 의 수치), 무중단 업그레이드 경로(ZDU)와 UI 다국어가 기본으로 켜지며, 브라우저·사용자 토큰으로는 저장된 시크릿 값을 읽을 수 없도록 복호화 가드가 강제됩니다. (업그레이드 시 조치 필요 — Breaking Changes 참조)  
  *구현: `global.datahub.version: v1.7.0.1`, upstream DataHub chart 1.0.0 → 1.1.6. 1.1.x 의 새 기본값(`systemUpdate.zdu.enable: true`, `encryptionKey.callerGuardMode: ENFORCE`, `i18n.enabled: true`)을 values 에 값으로 명시해 환경 간 차이를 막았습니다.*
- **폐쇄망 환경에서도 UI 수집 실행 가능**  
  UI 에서 만든 수집 소스가 실행 시점에 외부 패키지 저장소에서 CLI 를 내려받지 않고 이미지에 내장된 실행 환경을 씁니다. 외부 저장소에 해당 버전 패키지가 없어 수집이 실패하던 경우도 함께 사라집니다.  
  *구현: `managed_ingestion.defaultCliVersion: native`, Catalog Gateway 가 만드는 수집 소스의 CLI 버전 기본값도 `native`(`catalog-gateway.config.polaris.datahubIngestionCliVersion`, subchart 0.0.9).*
- **Iceberg(Polaris) 수집의 realm 헤더를 표준 방식으로 지정**  
  수집 레시피에 Polaris realm 을 pyiceberg 가 지원하는 표준 속성으로 넣습니다. 이전의 자체 패치는 제거되었고, 예전 형식의 레시피도 그대로 받아 주므로 기존 수집 소스를 고칠 필요가 없습니다. upstream 이 문서화한 방식이라 이후 DataHub 버전에서도 패치 없이 유지됩니다.  
  *구현: 레시피 `header.Polaris-Realm` 속성(upstream PR #18356 기준), Catalog Gateway 의 수집 소스 생성 코드와 커스텀 수집 이미지의 호환 shim.*
- **확장 수집 기능(view 수집·파티션 키 표시·증분 속성 반영)을 v1.7 기반으로 유지**  
  자체 확장 기능이 v1.7.0.1 소스 위에 다시 구현되어 업그레이드 뒤에도 같은 결과를 냅니다. 증분 속성 반영은 v1.7 의 processor 확장 방식으로 옮겨졌습니다.  
  *구현: 커스텀 datahub-actions 이미지 `v1.7.0.1-with-view-ldap-docs-partkey-incprops`.*
- **GitOps(ArgoCD) 환경에서 업그레이드 Job 이 안정적으로 실행**  
  무중단 업그레이드 경로에서는 필요 없는 임시 ServiceAccount hook 을 쓰지 않습니다. ArgoCD 가 hook 으로 만든 ServiceAccount 를 업그레이드 Job 실행 전에 지워 Pod 생성이 막히던 문제가 사라집니다.  
  *구현: `datahubSystemUpdate.serviceAccount.create: false`.*

## Fixes

- **역할 수가 많은 환경에서 UI 응답과 수집 작업이 느려지던 문제 해결**  
  v1.6.0 의 권한 평가 결함이 upstream v1.7.0 에서 수정되어 해소되었습니다. 역할 3,000 개 추가 조건에서 사용자 조회 201~285 ms → 52~65 ms, 권한 조회 180~185 ms → 17~48 ms 로 측정되었습니다(2026-10-07).  
  *구현: DataHub GMS `DataHubAuthorizer` upstream 수정분 포함.*
- **GMS 외부 노출(Ingress) 비활성 기본값이 공통 values 에서 빠져 있던 문제 복구**  
  공통 values 의 GMS 설정 블록이 갈라지면서 `ingress.enabled: false` 가 누락되어 있었습니다. 렌더 결과가 원래대로 돌아옵니다.  
  *구현: `values-override/base/common.yaml` 의 datahub-gms 블록 복구.*

## Known Issues

- **기존 UI 수집 소스에 구체 CLI 버전이 지정되어 있으면 수집 실행 불가**  
  업그레이드 전에 만든 수집 소스의 `config.version` 이 `1.6.0` 처럼 구체 버전이면 실행기가 패키지 다운로드 단계에서 실패합니다. 값을 `native` 로 바꾸면 회피할 수 있으며, 기존 소스를 일괄 변경하는 절차는 정리 중입니다.
- **UI 외 경로로 만든 변경의 인라인 색인 반영 지연 미측정**  
  v1.7.0 은 인라인(즉시) 색인을 UI 에서 들어온 변경에만 적용합니다. API 로 들어온 변경은 비동기 색인을 타며, 그 반영 지연은 아직 측정되지 않았습니다.
- **역할 멤버십 변경 API 에 Manage Policies 권한 필요**  
  v1.7.0 부터 역할 멤버십 쓰기에 정책 관리 권한이 요구됩니다. Catalog Gateway 를 통한 역할 관리는 시스템 자격으로 동작해 영향이 없고, DataHub API 를 직접 호출하는 클라이언트만 해당합니다.
- **kafka-setup 이미지 버전 지정 불가**  
  upstream DataHub chart 가 kafka-setup 이미지를 앱 버전과 별도로 고정(`v1.2.0.1`)하므로 다른 컴포넌트와 달리 버전을 바꿀 수 없습니다. upstream 의 의도된 값이며 결함이 아닙니다.
- **메타데이터 서비스 인증 기본 비활성, SSO/OIDC 미연계**  
  `metadata_service_authentication.enabled` 기본값은 `false` 이고 Frontend 는 로컬 계정으로 동작합니다. 상용 전환 시 결정이 필요한 항목으로 추적합니다. TODO(prod-5)
- **데이터베이스·정책 서버 접속 정보가 values 에 평문으로 저장됨**  
  PostgreSQL, Polaris 최초 관리 계정, OPAL 브로드캐스트 접속 정보가 values 평문입니다. Secret 또는 외부 비밀 저장소로 분리하는 작업을 추적합니다. TODO(prod-2)

## Upgrade Notes

**0.4.21 → 0.5.0**

- 앱 버전이 바뀌므로 업그레이드 시 **system-update(무중단 업그레이드 경로, 18단계)가 실행**됩니다. Job 이 완료(Succeeded)된 뒤 GMS 의 `/config` 응답에서 버전이 `v1.7.0.1`, 수집 CLI 기본값이 `native` 인지 확인하십시오. 검증 환경에서 GMS 시작까지 약 105 초가 걸렸습니다.
- chart 구조는 바뀌지 않아 ArgoCD Application 을 다시 적용할 필요는 없습니다. 다만 Breaking Changes 의 첫 항목대로 chart 버전 pin 과 values 를 함께 올리십시오. 폐쇄망 환경은 내부 chart 저장소에 0.5.0 을 먼저 넣으십시오.
- 반영 전 values 에서 다음을 확인하십시오. (1) `extraEnvs` 를 정의한 DataHub 컴포넌트에 시스템 클라이언트 환경 변수 2개 추가. (2) 커스텀 수집 이미지를 쓰는 환경은 datahub-actions 이미지 태그를 v1.7.0.1 계열로 변경. (3) `preProcessHooksUIEnabled` 와 `reProcessUIEventHooks` 를 둘 다 `false` 로 두면 chart 1.1.x 가 렌더에 실패하므로 기본값을 유지.
- MCP 서버를 http 방식으로 바꾸려면 `datahub-mcp.transport: http` 로 바꾸고 공유 토큰(`gms.token`)을 제거하십시오. 토큰이 남아 있으면 렌더가 실패해 설정 오류를 미리 알려 줍니다.
- 업그레이드 뒤 기존 수집 소스의 `config.version` 을 `native` 로 바꾸고, 수집을 한 번 실행해 성공을 확인하십시오. 검증 환경에서는 업그레이드 전후 엔티티 수(dataset·corpuser·role·container·domain)가 같고 수집 소스 12개가 유지되었습니다.

**0.4.8 이하에서 올리는 경우**

- 0.4.9 이상은 `catalog-gateway.image.tag` 가 환경 values 에 반드시 있어야 렌더됩니다. 위 절차에 더해 이 값을 먼저 채우십시오.
