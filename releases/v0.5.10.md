# MetaHub 0.5.10 (2026-11-17)

Release Note

## What's New

MetaHub 0.5.10 은 **AI 도구(MCP) 연동의 처리 용량을 키우고, chart 를 Apache Polaris 1.7.0 기준으로 맞춘** 릴리즈입니다. Polaris 1.7.0 이미지는 0.5.9 chart 에서 이미지 태그만 올려 먼저 적용할 수 있으며, 0.5.10 은 chart 의 Polaris 표기를 1.7.0 으로 맞추고 Polaris 1.7.0 이 새로 제공하는 확장 기능을 선택 설정으로 노출합니다(기본 꺼짐). Polaris 로 만든 뷰(view)가 이제 메타데이터 플랫폼에 자동으로 등록됩니다.

MCP 서버는 한 파드에서 여러 워커 프로세스를 띄울 수 있게 되어, 상용급 부하테스트에서 동시 사용자 1,000명 규모의 요청을 오류 없이 처리했습니다. 권한 데이터를 한곳에서 만들어 제공하는 새 컴포넌트(AuthzManager)를 선택 설정으로 추가했습니다.

## Breaking Changes

- 이번 릴리즈에 values 인터페이스 breaking change 없음 (0.5.9 → 0.5.10 기준). 새 설정은 모두 기본 꺼짐이거나 이전 동작과 같습니다.
- **chart 0.5.10 은 Polaris 1.7 이미지가 전제입니다.** chart 가 Polaris 1.7.0 용 설정 항목을 항상 내보내므로, 이전(1.6) 이미지인 채로 올리면 일부 요청이 실패합니다. 0.5.9 에서 Polaris 이미지를 1.7 로 먼저 올리십시오(Upgrade Notes 참조).

## Features

- **Apache Polaris 1.7.0 기준 chart**  
  chart 의 Polaris 버전 표기와 기본 이미지 태그를 1.7.0 으로 맞추었습니다. Polaris 1.7.0 이미지에는 테이블 커밋 경로의 데이터 손상 가능성 수정, 이벤트 ID 안정화, 인증 경로의 데이터베이스 조회 감소가 포함되며, 이 이미지는 0.5.9 chart 에서도 이미지 태그만 올려 적용할 수 있습니다. 기존 설정은 그대로 쓸 수 있고 데이터베이스 스키마 변경이 없습니다. 관리 콘솔도 1.7.0 으로 맞추었습니다.  
  *구현: polaris 서브차트 1.7.0 (앱 1.7.0), polaris-console 서브차트 0.1.7.*
- **Polaris 1.7.0 확장 기능 선택 설정**  
  카탈로그 이벤트를 Kafka 로도 내보내는 이벤트 리스너와, Iceberg 클라이언트가 보내는 스캔·커밋 리포트의 처리 방식을 values 로 고를 수 있습니다. 모두 기본 꺼짐입니다.  
  *구현: `polaris.eventListener.kafka.*`, `polaris.metricsReporting.type`(기본 `no-op`).*
- **Polaris 뷰(view) 메타데이터 자동 등록**  
  Polaris 로 뷰를 만들거나 바꾸거나 지우면 메타데이터 플랫폼에 뷰로 등록·갱신·삭제 처리됩니다. 이전에는 테이블만 반영되었습니다.  
  *구현: 이벤트 `AfterCreateView`·`AfterReplaceView`·`AfterDropView`, 하위 유형 `View`.*
- **MCP 서버 워커 수 설정**  
  MCP 서버(http 방식)가 한 파드에서 여러 워커 프로세스로 요청을 나눠 처리할 수 있습니다. 파드 수를 늘리지 않고 처리 용량을 키울 때 사용합니다. 기본값은 1 로 이전과 같습니다.  
  *구현: `datahub-mcp-http.workers` (http 전용).*
- **권한 데이터 전담 컴포넌트 AuthzManager (선택 설정)**  
  Catalog Gateway 의 각 프로세스가 따로 만들던 권한 데이터를 단일 인스턴스가 만들어 제공하는 컴포넌트를 추가했습니다. 이번 릴리즈에서는 기존 경로와 결과를 비교해 보는 단계로, 켜도 권한 판정 경로는 바뀌지 않습니다. 기본값은 꺼짐입니다.  
  *구현: `authz-manager` 서브차트 0.1.1, 상태·지표 `/v1/ready`·`/metrics`.*

## Improvements

- **AuthzManager 연결을 위한 네트워크 정책 사전 허용**  
  네트워크 정책을 켠 환경에서 정책 클라이언트와 Catalog Gateway 가 AuthzManager 에 접근할 수 있도록 허용 규칙을 추가했습니다. AuthzManager 를 쓰지 않으면 영향이 없습니다.  
  *구현: `opal.networkPolicy.authzManager.*`, `catalog-gateway.networkPolicy.authzManager.*`.*

## Fixes

- **MCP 권한 범위 적용을 우회할 수 있던 경로 차단**  
  MCP 권한 범위 적용을 켠 환경에서 Catalog Gateway 의 메타데이터 서비스 호환 경로를 직접 호출하면 권한 범위를 비켜 갈 수 있던 문제를 수정했습니다. 쓰기 요청은 거부하고(403), 식별자를 선택하지 않은 조회 결과와 집계 결과, SQL 예시에서 권한 없는 테이블의 정보가 보이지 않게 했습니다. MCP 도구를 통한 요청은 이전에도 영향이 없었습니다. chart 변경 없이 Catalog Gateway 이미지를 올리면 적용됩니다.
- **Polaris 1.7 에서 스캔·커밋 리포트 전문이 로그에 남던 문제 해결**  
  Polaris 1.7.0 의 기본 동작으로 Iceberg 클라이언트 리포트 전문이 로그에 기록되던 것을 막았습니다.

## Known Issues

- **높은 부하에서 권한 데이터 주기 갱신 시 일부 조회 지연**  
  0.5.9 노트와 같습니다. 이번 릴리즈의 AuthzManager 가 이 구조를 개선하기 위한 첫 단계이며, 전환은 후속 릴리즈에서 다룹니다.
- **외부 OPA 컨테이너만 단독 재시작되면 약 75초간 권한 확인이 거부됨**  
  0.5.9 노트와 같습니다.
- **Polaris 뷰 이름 변경은 메타데이터 플랫폼에 반영되지 않음**  
  뷰 생성·교체·삭제만 전달됩니다. 이름을 바꾼 뷰는 주기 수집으로 보정됩니다.
- **Polaris 시맨틱 모델 기능은 사용할 수 없음**  
  Polaris 1.7.0 에서 해당 API 가 아직 구현되지 않았습니다. 관련 기능 플래그를 켜지 마십시오.
- **테이블 수가 많은 환경에서 전체 테이블 목록 조회 시 Catalog Gateway 메모리 한도 초과 가능**, **역할(role) 등록 요청의 응답 지연 원인 미확정**, **기존 UI 수집 소스에 구체 CLI 버전이 지정되어 있으면 수집 실행 불가** — 0.5.9 노트와 같습니다.
- **시맨틱(벡터) 검색은 켠 상태 미검증**, **메타데이터 서비스 인증 기본 비활성·SSO/OIDC 미연계**, **접속 정보 values 평문 저장** — 0.5.9 노트와 같습니다.

## Deprecations

- **MCP sse 인스턴스(`datahub-mcp`) — 0.6 릴리즈에서 제거 예정**  
  0.5.9 노트와 같습니다. MCP 클라이언트를 Gateway 경유 http 인스턴스(`datahub-mcp-http`)로 먼저 옮기십시오.

## Upgrade Notes

**0.5.9 → 0.5.10**

- DataHub 앱 버전 변경이 없습니다(v1.7.0.1 유지). chart 의 Polaris 표기가 1.6.0 에서 1.7.0 으로 바뀌지만 데이터베이스 스키마 변경과 초기화 Job 재실행이 필요하지 않습니다.
- **0.5.10 으로 올리기 전에 `polaris.image.tag` 가 Polaris 1.7 빌드여야 합니다.** 0.5.9 에서 이미지 태그를 먼저 올려 두는 것을 권장합니다. 1.6 이미지인 채로 chart 를 올리면 Iceberg 클라이언트의 리포트 전송 요청이 500 으로 실패합니다. 이벤트 전달 기능이 포함된 빌드를 써야 하므로 `polaris.image` 오버라이드를 빠뜨리지 마십시오.
- 업그레이드 시 Polaris 가 한 번 롤링 재시작합니다(설정 항목 한 줄 추가).
- Polaris 뷰 자동 등록을 쓰려면 Catalog Gateway 이미지도 0.5.10 과 함께 배포된 빌드 이후로 올리십시오.
- **MCP 워커 수를 늘리는 경우**: `datahub-mcp-http.resources.limits.cpu` 를 워커 수 + 1 로 함께 올리십시오. MCP 서버만 늘리면 메타데이터 서비스, 데이터베이스 연결 풀, Catalog Gateway 순으로 다음 한계에 닿으므로 함께 증설을 검토하십시오.
- **AuthzManager 를 켜는 경우**: `authz-manager.image.tag` 가 필수이며, Polaris 데이터베이스와 메타데이터 서비스 접속 값을 `authz-manager.config.*` 에 Catalog Gateway 와 같은 값으로 넣으십시오. Ingress 는 API 에 인증이 없으므로 접근 범위를 제한할 수 있을 때만 켜십시오.
- **Polaris Kafka 이벤트 리스너를 켜는 경우**: 토픽을 미리 만들고, 네트워크 정책을 켠 환경은 Kafka 로 나가는 규칙을 추가하십시오. 확장 설정을 넣은 뒤 이미지만 1.6 으로 되돌리면 Polaris 가 시작하지 못하므로, 되돌릴 때는 확장 설정도 함께 빼십시오.

**이전 버전(0.5.0 ~ 0.5.8)에서 올리는 경우**

- 0.5.9 노트의 Upgrade Notes 를 먼저 따르십시오. 0.5.9 는 Catalog Gateway 이미지를 함께 올려야 합니다.
