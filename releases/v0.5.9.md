# MetaHub 0.5.9 (2026-11-09)

Release Note

## What's New

MetaHub 0.5.9 는 **정책 엔진(OPAL)을 안정화 버전으로 올리고, AI 도구(MCP) 경유 요청의 추적과 오류 진단을 강화한** 릴리즈입니다. 정책 서버와 클라이언트를 OPAL 0.9.9 로 올려, 정책 브로드캐스트용 데이터베이스 연결이 끊겨도 자동으로 다시 연결하고 놓친 변경을 다시 동기화합니다. 정책 판정 결과는 이전과 같으며, 상용급 부하테스트에서 성능도 이전 버전과 같았습니다.

함께 정책 엔진(OPA)을 최신 공식 이미지의 별도 컨테이너로 띄우는 선택 설정을 추가했습니다. 켜면 같은 정책·데이터로 판정은 같게 유지하면서 높은 부하에서 권한 확인 응답의 꼬리 지연이 30~40% 줄어듭니다. 기본값은 꺼짐입니다. Catalog Gateway 는 MCP 경유 요청의 상세 이력을 남길 수 있게 되었고, 데이터셋 등록·일괄 업로드 실패를 원인별 오류 코드로 알려 줍니다.

## Breaking Changes

- 이번 릴리즈에 values 인터페이스 breaking change 없음 (0.5.8 → 0.5.9 기준). 새 설정은 모두 기본 꺼짐입니다.
- **chart 0.5.9 는 Catalog Gateway 이미지도 함께 올려야 합니다.** chart 가 새 설정 항목을 항상 내보내므로, 그 항목을 모르는 이전 Gateway 이미지는 시작하지 못합니다(Upgrade Notes 참조).
- Catalog Gateway 의 미사용 API `GET /v1/rbac/roles/{role_id}/namespace-grant-status` 가 제거되었고, 메타데이터 일괄 업로드(`POST /v1/enrichment/bulk-csv`)의 요청당 행수 상한이 10,000 에서 2,000 으로 낮아졌습니다.

## Features

- **정책 엔진(OPA)을 최신 공식 이미지의 별도 컨테이너로 실행**  
  정책 클라이언트에 내장된 OPA 대신 최신 공식 OPA 를 같은 파드의 별도 컨테이너로 띄우고 정책·권한 데이터를 그쪽에 넣습니다. 같은 입력에 대한 판정은 내장 OPA 와 같고(검증 코퍼스 불일치 0건), 정책 평가가 빨라져 높은 부하에서 권한 확인 응답의 p95 지연이 30~40% 줄었습니다. 서비스 포트와 연결 방식이 그대로라 다른 컴포넌트는 바꿀 필요가 없습니다. 기본값은 꺼짐입니다.  
  *구현: `opal.opa.external.enabled` (기본 이미지 `openpolicyagent/opa:1.21.3`), 켜는 조합 `values-override/features/opa-external.yaml`.*
- **MCP 경유 요청의 상세 이력 기록**  
  AI 도구가 MCP 를 통해 보낸 검색·조회 요청마다 어떤 질의가 들어왔고 권한 범위가 어떻게 적용되었는지(적용 범위, 응답에서 제외된 건수, 클라이언트 종류)를 요청 이력과 같은 ID 로 한 줄 더 남깁니다. 응답 본문은 저장하지 않습니다. 기본값은 꺼짐입니다.  
  *구현: `catalog-gateway.historyLog.detail.enabled` → 이력 저장소의 `detail/` 폴더.*
- **사용자 지정 역할이 부여한 리소스 조회**  
  특정 사용자·부서·그룹에게 사용자 지정 역할이 허용한 리소스를 목록과 역할별 묶음으로 한 번에 확인할 수 있습니다.  
  *구현: Catalog Gateway `GET /v1/rbac/resources/custom-granted`.*

## Improvements

- **정책 브로드캐스트 연결이 끊겨도 자동 복구**  
  정책 서버가 브로드캐스트용 데이터베이스 연결 끊김을 감지하면 자동으로 다시 연결하고, 끊긴 동안의 변경은 버리지 않고 보류했다가 연결된 클라이언트를 다시 동기화합니다. 이전에는 같은 상황에서 정책 서버 프로세스가 통째로 재시작되며 클라이언트 연결이 흔들렸습니다. 별도 설정 없이 적용됩니다.  
  *구현: OPAL 0.9.3 → 0.9.9 (opal-server·opal-client 기본 이미지), 내장 OPA 1.9.0 은 동일.*
- **데이터셋 등록·삭제 실패를 원인별 오류 코드로 응답**  
  메타데이터 서비스 장애, 동시 쓰기 충돌, 잘못된 요청 등을 오류 코드와 재시도 가능 여부, 실패 단계로 구분해 알려 줍니다. 여러 데이터셋을 한 번에 등록할 때 일부가 실패해도 나머지는 끝까지 처리하고 항목별 결과를 돌려줍니다.  
  *구현: `error_code`(8종)·`retryable`·`stage`·`remediation`, 일괄 등록은 `metadata.debug_info` 집계.*
- **메타데이터 일괄 업로드의 행별 오류 세분화**  
  CSV 일괄 업로드의 각 행이 왜 실패했는지 오류 코드·실패 단계·재시도 가능 여부로 알려 주고, 일부 단계만 반영된 행은 부분 성공으로 따로 셉니다.  
  *구현: 행 결과 `error_code`(6종)·`stage`·`retryable`·`failed_steps`, 요약 `partial`·`errors_by_code`.*
- **MCP 권한 범위 적용 시 사용자를 식별할 수 없는 요청 거부**  
  MCP 권한 범위 적용을 켠 환경에서 토큰에 사용자 식별 정보가 없으면, 이전에는 시스템 권한 범위로 응답했지만 이제 403 으로 거부합니다.  
  *구현: `MCP_SCOPE.REQUIRE_CALLER`(기본 true), 응답 detail_code 4036.*

## Fixes

- **외부 OPA 를 켠 채 업데이트할 때 정책 클라이언트가 한 번씩 재시작되던 문제 해결**  
  롤링 업데이트에서 정책 클라이언트가 OPA 보다 먼저 시작해 첫 정책 적재에 실패하고, 약 5분 뒤 재시작하던 문제를 수정했습니다. 이 지연 때문에 배포 도구가 업그레이드를 실패로 표시하던 현상도 사라집니다.  
  *구현: OPA 컨테이너 우선 시작 + 정책 저장소 연결 재시도(`opal.opa.external.storeConnRetry`).*
- **메타데이터 서비스 장애가 권한 오류로 표시되던 문제 해결**  
  일괄 업로드 중 메타데이터 서비스에 연결하지 못하면 "오너가 아닙니다"(403)로 응답하던 문제를 수정했습니다. 이제 서비스 일시 장애(503)로 알려 줍니다.
- **큰 일괄 업로드 요청이 응답 없이 끊기던 문제 해결**  
  행이 많은 CSV 업로드가 처리 시간 한도를 넘어 응답 없이 끊기던 문제를 수정했습니다. 처리 중에도 서버가 정상 상태를 유지하며, 한 요청은 2,000행까지 받습니다.

## Known Issues

- **높은 부하에서 권한 데이터 주기 갱신 시 일부 조회 지연**  
  동시 사용자 2,000명 규모의 부하에서 권한 데이터 주기 갱신(기본 10분)과 겹치면 약 70초 동안 사용자별 리소스 조회의 p95 지연이 약 2.5초로 늘어납니다. 권한 판정(OPA) 경로는 영향이 없습니다. 권한 데이터 생성 구조 개선을 후속 릴리즈에서 다룹니다.
- **외부 OPA 컨테이너만 단독 재시작되면 약 75초간 권한 확인이 거부됨**  
  외부 OPA 설정을 켠 뒤 OPA 컨테이너만 재시작되면 정책이 비어, chart 의 상태 점검이 정책 클라이언트를 재시작해 다시 채울 때까지 권한 확인이 거부됩니다. 메모리 한도를 넉넉히 두고 정책 클라이언트를 2개 이상 운영하십시오.
- **테이블 수가 많은 환경에서 전체 테이블 목록 조회 시 Catalog Gateway 메모리 한도 초과 가능**  
  0.5.8 노트와 같습니다. 환경 values 의 bulkhead 전용 그룹(동시 1건)으로 회피할 수 있습니다.
- **역할(role) 등록 요청의 응답 지연 원인 미확정**  
  0.5.8 노트와 같습니다.
- **기존 UI 수집 소스에 구체 CLI 버전이 지정되어 있으면 수집 실행 불가**  
  `config.version` 을 `native` 로 바꾸면 회피할 수 있습니다.
- **시맨틱(벡터) 검색은 켠 상태 미검증**, **메타데이터 서비스 인증 기본 비활성·SSO/OIDC 미연계**, **접속 정보 values 평문 저장** — 0.5.8 노트와 같습니다.

## Deprecations

- **MCP sse 인스턴스(`datahub-mcp`) — 0.6 릴리즈에서 제거 예정**  
  0.5.8 노트와 같습니다. MCP 클라이언트를 Gateway 경유 http 인스턴스(`datahub-mcp-http`)로 먼저 옮기십시오.

## Upgrade Notes

**0.5.8 → 0.5.9**

- DataHub 와 Polaris 앱 버전 변경이 없습니다(DataHub v1.7.0.1, Polaris 1.6.0 유지). 스키마 변경과 초기화 Job 재실행이 필요하지 않습니다.
- **`catalog-gateway.image.tag` 를 0.5.9 와 함께 배포된 Gateway 빌드 이후로 올리십시오.** 이전 이미지는 chart 가 내보내는 `HISTORY_LOG.DETAIL_ENABLED` 항목을 알지 못해 시작하지 못합니다(로그 `Extra inputs are not permitted`). 새 이미지는 설정을 따로 넣지 않아도 됩니다.
- 정책 서버·클라이언트 기본 이미지가 `permitio/opal-server:0.9.9`·`permitio/opal-client:0.9.9` 로 바뀝니다. 사설 미러를 쓰는 환경은 업그레이드 전에 이 이미지를 받을 수 있는지 확인하십시오. 업그레이드 시 정책 서버·클라이언트가 한 번씩 롤링 재시작합니다.
- 브로드캐스트 데이터베이스(`opal.broadcastUri`)를 쓰는 환경은 정책 서버 상태 점검(`/healthcheck`)이 브로드캐스트 연결 상태를 반영합니다. 데이터베이스 장애가 정책 서버 점검 실패로 보이므로, 이 알람이 뜨면 데이터베이스부터 확인하십시오. `opal.broadcastKeepaliveInterval` 설정은 계속 필요하니 지우지 마십시오.
- `POST /v1/enrichment/bulk-csv` 를 2,000행보다 큰 파일로 호출하는 클라이언트는 파일을 나누어 올리십시오. `namespace-grant-status` API 를 호출하는 클라이언트가 있다면 제거하십시오.
- **외부 OPA 를 켜는 경우**: 사설 미러에 `openpolicyagent/opa:1.21.3` 을 준비하고, 권한 데이터 메모리가 OPA 컨테이너로 옮겨 가므로 `opal.opa.external.resources` 의 메모리 한도를 기존 정책 클라이언트 기준으로 잡으십시오. 끄면 내장 OPA 로 돌아갑니다(롤링 1회).

**이전 버전(0.5.0 ~ 0.5.6)에서 올리는 경우**

- 0.5.8 노트의 Upgrade Notes 를 먼저 따르십시오. 0.5.1~0.5.8 에서 추가된 설정은 모두 기본 꺼짐입니다.
