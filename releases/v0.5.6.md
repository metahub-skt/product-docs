# MetaHub 0.5.6 (2026-10-15)

Release Note

## What's New

MetaHub 0.5.6 은 **빈 PostgreSQL 에서 chart 만으로 설치가 끝나도록 Polaris 데이터베이스 초기화를 chart 에 내장한** 릴리즈입니다. 이전까지는 Polaris 가 쓰는 스키마와 최초 관리 계정(realm root principal)을 환경별 values 의 init container 에 손으로 복사해 두어야 했고, 그 복사본이 빠진 환경에서는 Polaris 가 시작 직후 "relation does not exist" 오류를 내며 Catalog Gateway 까지 연쇄 재시작했습니다. 이제 선택 옵션 하나로 역할·데이터베이스·확장·스키마·관리 계정 시드까지 chart 가 멱등하게 만들어 줍니다. 기본값은 꺼져 있어 기존 환경의 동작은 바뀌지 않습니다.

함께 Catalog Gateway 의 요청 이력(history) 로그에서 두 종류의 요청이 기록되지 않던 문제를 수정했습니다.

## Breaking Changes

- 이번 릴리즈에 breaking change 없음 (0.5.5 → 0.5.6 기준). values 인터페이스와 기본값은 변경되지 않았으며, 새 옵션 `polaris.dbInit` 은 기본 꺼짐입니다.

## Features

- **빈 데이터베이스에서 추가 준비 작업 없이 Polaris 설치 가능**  
  PostgreSQL 에 아무것도 없어도 chart 가 Polaris 용 역할과 데이터베이스, pgcrypto 확장, 스키마(v3), 최초 관리 계정을 순서대로 만듭니다. 여러 번 실행해도 결과가 같아 재설치·복구 시에도 그대로 쓸 수 있습니다. 데이터베이스가 고가용성 구성이면 노드 목록에서 primary 를 찾아 접속합니다. 기본값은 꺼짐이며, 켜는 방법은 Upgrade Notes 에 있습니다.  
  *구현: Polaris subchart 1.6.1 의 init container `polaris.dbInit` (enabled · hosts · port · retries · superuserSecret). 관리 계정 비밀번호는 `bootstrapCredentials` 값의 sha256(secret:salt) 과 랜덤 salt 로 저장합니다.*

## Improvements

- **설치 초기화 상태를 점검하고 단계별로 다시 수행하는 스크립트 제공 (개발·검증 환경용)**  
  설치 후 데이터베이스 계정·스키마·접속 설정이 준비되었는지 한 번에 점검하고, 빠진 단계만 골라 다시 수행하거나 전체를 초기 상태로 되돌릴 수 있습니다. 새 환경을 처음 올릴 때 원인 추적 시간을 줄여 줍니다.  
  *구현: `scripts/local-metahub-init.sh` 계열 스크립트.*

## Fixes

- **Catalog Gateway 요청 이력 로그에 일부 요청이 기록되지 않던 문제 해결**  
  처리되지 않은 예외로 500 응답이 난 요청과, DataHub API 를 그대로 중계하는 경로(`/openapi`)의 요청이 이력 로그에 남지 않았습니다. 이제 두 경우 모두 다른 요청과 같은 형식으로 기록됩니다. 로그 라인이 분할되거나 식별자가 빠진 것이 아니라 두 경로가 아예 기록되지 않던 것이 원인이었습니다.  
  *구현: Catalog Gateway history 로깅 미들웨어의 예외 경로·미러 경로 처리.*

## Known Issues

- **테이블 수가 많은 환경에서 전체 테이블 목록 조회 시 Catalog Gateway 메모리 한도 초과 가능**  
  전체 테이블 목록 API(`/v1/catalogs/all_tables`)는 결과 상한 없이 모두 모아 응답하며, 검색어가 카탈로그 이름에도 부분 일치합니다. 짧은 검색어로 10만 건 이상이 걸리면 요청 하나가 약 0.6~0.95 GB 의 메모리를 쓰고, 상용급 Kubernetes 환경의 1,000 동시 사용자 부하테스트(2026-10-16)에서 Gateway Pod 2개가 메모리 한도(8Gi)를 넘어 재시작했습니다. 이 릴리즈에서 새로 생긴 현상이 아니라 기존 동작의 한계입니다. 환경 values 의 bulkhead 에 이 경로 전용 그룹(동시 1건)을 두고, 전체 테이블 수와 worker 수에 맞춰 메모리 한도를 정하면 회피할 수 있습니다(실사용처럼 카탈로그 범위를 지정해 호출하면 같은 부하에서 실패 0 · 402 RPS · p99 440 ms 로 측정되었습니다). 결과 상한과 메모리 절감은 후속 릴리즈에서 다룹니다.
- **큰 카탈로그의 전체 목록 조회가 몰리면 작은 카탈로그의 같은 조회 일부가 503 으로 거절됨**  
  위 bulkhead 그룹은 경로 단위라, 응답에 수 초가 걸리는 큰 카탈로그 조회가 슬롯을 점유하면 같은 경로의 작은 조회가 대기 후 거절됩니다(부하테스트에서 1.5~3.9%). 다른 API 는 영향을 받지 않습니다. 현상만 기록되었고 수정은 보류 상태입니다.
- **역할(role) 등록 요청의 응답 지연 원인 미확정**  
  역할 수천 건 규모의 환경에서 역할 등록 1건에 약 14초가 걸리고 관리 목록 조회가 간헐적으로 500 을 냅니다(2026-10-16 측정). 권한 평가와 MCP 범위 적용 등 읽기 경로에는 영향이 없습니다. 원인 분리는 진행 중입니다.
- **기존 UI 수집 소스에 구체 CLI 버전이 지정되어 있으면 수집 실행 불가**  
  DataHub v1.7 계열에서 수집 소스의 `config.version` 이 `1.6.0` 처럼 구체 버전이면 executor 가 패키지 다운로드 단계에서 실패합니다. 값을 `native` 로 바꾸면 회피할 수 있으며, 기존 소스를 일괄 변경하는 절차는 정리 중입니다.
- **시맨틱(벡터) 검색은 켠 상태 미검증**  
  0.5.1 에서 추가된 on/off 설정은 꺼진 상태로만 검증되었습니다. 임베딩 서버가 준비되는 대로 켠 상태를 검증할 예정입니다.
- **kafka-setup 이미지 버전 지정 불가**  
  upstream DataHub chart 가 kafka-setup 이미지를 앱 버전과 별도로 고정(`v1.2.0.1`)하므로, 다른 컴포넌트와 달리 버전을 바꿀 수 없습니다. upstream 의 의도된 값이며 결함이 아닙니다.
- **메타데이터 서비스 인증 기본 비활성, SSO/OIDC 미연계**  
  `metadata_service_authentication.enabled` 기본값은 `false` 이고 Frontend 는 로컬 계정으로 동작합니다. 상용 전환 시 결정이 필요한 항목으로 추적합니다. TODO(prod-5)
- **데이터베이스·정책 서버 접속 정보가 values 에 평문으로 저장됨**  
  PostgreSQL, Polaris 최초 관리 계정, OPAL 브로드캐스트 접속 정보가 values 평문입니다. Secret 또는 외부 비밀 저장소로 분리하는 작업을 추적합니다. TODO(prod-2)

## Deprecations

- **MCP sse 인스턴스(`datahub-mcp`) — 0.6 릴리즈에서 제거 예정 (2026-11 계획)**  
  MCP 클라이언트가 Gateway 경유 http 인스턴스(`datahub-mcp-http`, `/mcp` + JWT)로 전환되면 공유 토큰 기반 sse 인스턴스와 `/sse` 전제를 제거합니다. 그 릴리즈가 breaking change 가 되며, 해당 Release Note 에서 다시 공지합니다. 제거 전에 `/sse` 를 쓰는 클라이언트를 먼저 옮기십시오.

## Upgrade Notes

**0.5.5 → 0.5.6**

- 앱 버전 변경이 없습니다(DataHub v1.7.0.1, Polaris 1.6.0 유지). 스키마 변경과 초기화 Job 재실행이 필요하지 않습니다.
- chart 구조 변경이 없어 ArgoCD Application 을 다시 적용할 필요가 없습니다. 환경의 chart 버전 pin 만 0.5.6 으로 올리십시오.
- values 기본값 변경이 없으므로 override 를 쓰는 환경도 확인 항목이 없습니다.
- **Polaris 데이터베이스 초기화를 chart 에 맡기려는 환경**은 `polaris.dbInit.enabled: true` 와 함께 `polaris.dbInit.hosts` 에 PostgreSQL **노드**의 headless 주소를 순서대로 적으십시오. 연결 풀(pgpool) 주소는 쓸 수 없습니다(슈퍼유저 인증이 거부됩니다). 슈퍼유저 비밀번호는 `polaris.dbInit.superuserSecret` 이 가리키는 Secret 에 두십시오. 이미 자체 init container 로 스키마를 시드하던 환경은 그대로 두어도 되고, 둘 다 켜도 결과는 같습니다.

**이전 버전(0.4.x)에서 올리는 경우**

- 0.5.0 에서 DataHub 가 v1.6.0 에서 v1.7.0.1 로 바뀌었습니다. 같은 values 로도 결과가 달라지므로 **chart 버전과 values 를 함께** 올리십시오. 업그레이드 시 system-update(무중단 업그레이드 18단계)가 실행됩니다.
- DataHub v1.7 은 `DATAHUB_SYSTEM_CLIENT_ID` 와 `DATAHUB_SYSTEM_CLIENT_SECRET` 환경 변수가 없으면 GMS 와 system-update 가 시작하지 못합니다. chart 는 메타데이터 서비스 인증이 꺼진 상태에서 이 값을 렌더하지 않으므로 각 컴포넌트의 `extraEnvs` 로 넣어야 하며, `extraEnvs` 는 목록이라 환경 values 가 같은 컴포넌트의 `extraEnvs` 를 정의하면 **그 목록에도 두 항목을 추가**하십시오. 빠진 컴포넌트만 시작에 실패합니다.
- 기존 UI 수집 소스의 `config.version` 을 `native` 로 바꾸십시오(Known Issues 참조).
- 0.5.1~0.5.5 에서 추가된 설정(`semantic_search`, `datahub-mcp-http`, `mcpScope`, `opa.internalRoledataWithDatahub`)은 모두 기본 꺼짐이라 버전만 올리면 동작이 바뀌지 않습니다. 켤 때는 해당 버전의 Release Note 에 있는 "켜기 전 확인" 항목을 먼저 보십시오.
